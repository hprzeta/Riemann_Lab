1. Nombre de termes Riemann-Siegel

La formule de Riemann-Siegel calcule $Z(t)$ comme une somme de $N_{\text{termes}}$ termes :

$$Z(t) = 2\sum_{n=1}^{N_{\text{termes}}} \frac{\cos(\theta(t) - t\ln n)}{\sqrt{n}} + \text{terme de reste}, \qquad N_{\text{termes}}(t) = \left\lfloor\sqrt{\frac{t}{2\pi}}\right\rfloor$$

Chaque terme nécessite un calcul de cosinus et une division. Le coût par appel $Z(t)$ croît donc en $O(\sqrt{t})$.

3. Répartition du temps CPU — run T=100 000 (v6)

L'affinage Illinois est le goulot principal : 83 % du temps CPU, contre <1 % pour la détection de signes.

Camembert animé — Temps CPU par composant
illinois_C (affinage 170 bits) — 83 % overhead Python/multiprocessing — 11 % scan_arb (détection Z_double) — 5.7 % détection signe numpy — 0.2 % Turing-Backlund validation — 0.1 %

Le bottleneck est l'affinage Illinois à 170 bits (PREC=170, libmpfr). La v7 ciblera une réduction de N_termes par segmentation adaptative.

4. Levier v7 — N_termes adaptatif

L'idée v7 : limiter N_termes à un maximum N_max pour les grandes valeurs de t, en échange d'une légère perte de précision sur Z(t) (compensée par l'affinage Illinois).
